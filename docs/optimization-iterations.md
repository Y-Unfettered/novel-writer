# 六轮优化记录

## 第 1 轮：章节计划板自动推进

本轮目标：让 `planning/chapter-plan.md` 不再只是手工记录，而是跟着正文与摘要流程自动变化。

已完成：
- 新增章节计划行自动插入/更新逻辑，按章节号稳定定位和排序。
- `续写` / `跳转` 生成提示词时，自动把目标章节状态标成 `草稿`。
- `保存章节正文` 后，自动把对应章节状态推进到 `已成稿`。
- `保存章节摘要` 后，自动把对应章节状态推进到 `已更新摘要`。
- 自动同步章节标题，并在备注列写入当前待办状态，减少手动维护成本。

备份：
- [iteration-01](D:/小说/backups/iteration-01)

## 第 2 轮：摘要后的资料更新提示词补齐

本轮目标：把“保存章节摘要”之后需要维护的资料继续自动化，不只更新全局摘要和人物关系。

已完成：
- 新增时间线更新提示词。
- 新增章节计划板更新提示词。
- 新增角色卡更新提示词。
- `保存章节摘要` 后会同时输出：全局摘要、人物关系、时间线、章节计划，以及最多 3 张相关角色卡的更新提示词。
- 角色卡匹配按章节摘要中的角色名做快速筛选，避免每次全量更新所有角色卡。

备份：
- [iteration-02](D:/小说/backups/iteration-02)

## 第 3 轮：阶段复盘命令

本轮目标：补一个适合长篇中途校准方向的“范围复盘”能力。

已完成：
- 新增 `/novel 复盘 [起始章] [结束章]` 命令。
- 可按章节范围汇总摘要，并结合全局摘要、时间线、章节计划生成阶段复盘提示词。
- 默认支持直接复盘最近几章，适合写到中段时快速回看主线推进和伏笔状态。

备份：
- [iteration-03](D:/小说/backups/iteration-03)

## 第 4 轮：下一章规划命令

本轮目标：让工具不只接收你给的章节要点，也能基于现有资料反向给出下一章规划。

已完成：
- 新增 `/novel 规划下一章 [章节号]` 命令。
- 规划会综合全局摘要、时间线、章节计划板和最近章节摘要。
- 输出包含：本章目标、建议推进的冲突、建议出场人物、伏笔推进方向、场景基调，以及可直接交给 `续写` 的要点草案。
- 支持附加用户意图，让规划结果更贴近你当前想写的方向。

备份：
- [iteration-04](D:/小说/backups/iteration-04)

## 第 5 轮：上下文诊断命令

本轮目标：让作者能直接看到系统究竟带了哪些资料进入 prompt，便于查 token 和排查上下文偏差。

已完成：
- 新增 `/novel 上下文 [章节号]` 命令。
- 可直接显示当前组装到 prompt 里的角色卡、风格卡、最近章节和摘要范围。
- 输出细分 token 统计：全局摘要、时间线、章节计划、角色卡、最近摘要、最近正文、风格卡、用户要点。
- 同时打印最终组装后的上下文正文，方便调 prompt 和诊断为什么模型会偏题。

备份：
- [iteration-05](D:/小说/backups/iteration-05)

## 第 6 轮：项目快照能力

本轮目标：把“关键节点留档”也内建进工具，降低大改剧情和集中改稿时的回退成本。

已完成：
- 新增 `/novel 快照 [名称]` 命令。
- 快照会复制核心项目资料：`novel.json`、`global-summary.md`、`chapters/`、`characters/`、`planning/`、`references/`。
- 快照保存在 `snapshots/时间戳-名称/` 下，并附带 `SNAPSHOT.md` 记录创建时间和当前章节。
- 适合在大修前、卷末定稿前、重建资料前使用。

备份：
- [iteration-06](D:/小说/backups/iteration-06)
