# AI 小说长篇写作辅助工具

这是一个面向长篇小说创作的 AI 辅助工具。核心思路是：

- 作者自己控制主线剧情、章节目标和关键设定
- 工具负责组织上下文、生成提示词、维护摘要与结构化资料
- 每本小说独立存放，避免多本小说之间互相污染

## 当前版本要点

- 工具代码和小说数据已经分离
- 默认使用“一个文件夹代表一本小说”的结构
- 新建小说时，项目会默认创建到 `小说管理/<小说名>`
- 章节计划现在同时维护：
  - `planning/chapter-plan.md`
  - `planning/chapter-plan.json`
- 上下文组装支持：
  - 全局摘要
  - 时间线
  - 章节计划
  - 角色卡
  - 最近章节摘要
  - 最近完整正文
  - 风格参考卡
- 已内置：
  - 一致性检查
  - 阶段复盘
  - 下一章规划
  - 上下文诊断
  - 项目快照

## 使用方式

### 1. 安装与构建

```bash
npm install
npm run build
```

### 2. 运行测试

```bash
npm test
```

测试报告会输出到：

- [docs/test-report.md](/D:/小说/docs/test-report.md)

### 3. 新建小说

在工具根目录 `D:\小说` 下执行：

```text
/novel 新建
# 标题：神庙逃亡
# 作者：你的名字
# 设定：世界观、背景、主角、风格方向……
```

默认会创建到：

```text
小说管理/神庙逃亡
```

如果你想自定义目录名，可以额外提供：

```text
# 目录：temple-run
```

这样会创建到：

```text
小说管理/temple-run
```

### 4. 进入对应小说目录

创建完成后，进入该小说目录再继续使用其他命令：

```bash
cd "D:\小说\小说管理\神庙逃亡"
```

后续所有生成内容都会只落在这个目录里，不会污染其他小说。

## 标准工作流

### 第一步：规划章节

```text
/novel 规划章节 3 第三章标题
本章想表达的内容……
```

这一步只记录你的本章需求，不直接写正文。

### 第二步：确认章节方案

```text
/novel 确认章节 3 第三章标题
1. 本章目标……
2. 关键冲突……
3. 章节结尾钩子……
```

这一步用于把本章结构、冲突、出场人物、伏笔和结尾先确认清楚。

### 第三步：写正文

先准备正文写作上下文：

```text
/novel 写正文 3 第三章标题
```

这一步之后，不需要你再把正文贴回命令。

正确流程是：

- 助手根据当前上下文直接生成正文
- 助手直接写入 `chapters/drafts/03-draft.md`
- 你直接打开草稿文件修改

### 第四步：保存定稿

```text
/novel 保存定稿 3 第三章标题
```

这一步会同时完成：

- 保存正式正文到章节目录
- 自动生成章节摘要
- 自动同步全局摘要、人物关系、时间线、章节计划、相关角色卡

工具会直接读取当前草稿文件内容收口。只有在你明确想跳过草稿文件时，才需要额外附正文。

### 第五步：人工覆盖摘要（可选）

如果你不满意自动摘要，可以手工覆盖：

```text
/novel 保存章节摘要 3
<修改后的章节摘要>
```

这会再次自动同步全局资料。

## 配置项

每本小说项目的 `novel.json` 中会保存配置：

```json
{
  "config": {
    "maxGlobalSummaryTokens": 1500,
    "maxRecentFullChapters": 3,
    "maxRecentChapterSummaries": 5,
    "maxContextTokens": 5500,
    "maxCharacterCards": 6,
    "maxStyleReferences": 4
  }
}
```

含义：

- `maxGlobalSummaryTokens`
  - 全局摘要的目标上限
- `maxRecentFullChapters`
  - 上下文里最多保留几章完整正文
- `maxRecentChapterSummaries`
  - 上下文里最多保留几章摘要
- `maxContextTokens`
  - 整体上下文预算
- `maxCharacterCards`
  - 一次最多带入多少张角色卡
- `maxStyleReferences`
  - 一次最多带入多少张风格卡

## 自动上下文策略

当前裁剪优先级：

1. 先减少最近完整正文
2. 再减少最近章节摘要
3. 再减少风格参考卡
4. 再减少角色卡
5. 如果仍超预算，会把最后一章正文压成“结尾节选”
6. 如果仍超预算，会把最后一章摘要压成“压缩版摘要”

## 快照与安全

如果你准备大改剧情、重构资料或集中改稿，建议先创建快照：

```text
/novel 快照 卷一改稿前
```

快照会复制小说目录中的核心资料，便于回退。

## 风格素材建议

如果你有自己喜欢的环境描写、人物描写或打斗描写，不建议直接每次把大段原文塞进上下文。更推荐：

1. 保存原始素材

```text
/novel 保存素材 环境 山雨夜林
```

2. 生成风格卡提示词

```text
/novel 分析素材 环境 山雨夜林
```

3. 保存风格卡

```text
/novel 保存风格卡 环境 山雨夜林
```

4. 在续写时按需调用

```text
/novel 续写
调用风格：环境，动作
本章要点……
```

## 现在这套结构适合什么场景

适合：

- 同一个工具长期维护多本小说
- 每本小说独立积累摘要、角色卡、时间线、素材
- 在不同小说之间切换写作而不串上下文

不建议：

- 把多本小说数据直接混在工具根目录
- 在工具根目录直接执行非当前小说的写作命令

正确做法始终是：

1. 在工具根目录创建小说项目
2. 进入具体小说目录
3. 在该目录内继续写作
